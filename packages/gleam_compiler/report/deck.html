Handlers without stacks

Compiling EYG effect handlers to JavaScript with generalized evidence passing, generators for comparison, and effects for the browser built on top.

Forty minutes. Three parts: how evidence passing compiles handlers without capturing stacks, what generators give and cost, and what effect APIs for the browser look like once the compiler is fast. Every number is measured, Bun and Chromium, runs pooled.
EYG in one slide

Everything outside the program is an effect

  • Structural types, inferred, with effect rows on every function
  • No mutation, no exceptions, no FFI: a script can only perform
  • The runtime decides what an effect does, the CLI and the browser differ
  • Programs are an IR tree, hashed and shared as packages
// every effect the type allows is visible
(url) -> {
  let response = perform Fetch(url)
  let _ = perform Print("got it")
  response.status
}
// : (Request) -> <Fetch, Print> Int
The audience knows algebraic effects. The EYG specifics that matter for compilation are next.
What the compiler has to support

Deep, multi-shot, first class

handle Choose((options, resume) -> {
  // resume once per option
  !list_fold(options, 0, (col, acc) -> {
    !int_add(acc, resume(col))
  })
}, (_) -> {
  let col = perform Choose(columns)
  ...
})
  • One operation per label, a clause is (value, resume) -> …
  • Resuming reinstalls the handler
  • resume is a value: call it zero, one or many times, return it
  • Handlers are values too, nothing is syntax the compiler can pattern match on
  • Rows are open and generalised at let
Handlers as values rules out the easy trick of recognising a handler literal at the handle site. The old README even asked how tail resumption could be detected if the handler is a variable. Answer later: mark the function value.
The starting point

A free monad that bubbles, and some older bugs

let bind = (m, then) => {
  if (!(m instanceof Eff)) return then(m);
  let k = (x) => bind(m.k(x), then);
  return new Eff(m.label, m.value, k);
};
  • Every effectful let allocates a continuation
  • Every perform climbs through every handler
  • list_fold applied the reducer in the wrong order
  • int_compare never returned Gt
  • String literals were HTML escaped
found by running the shared spec suites and a differential test against the interpreter
Not a criticism, the README was honest that this was the simple version. The bugs were invisible because there were no tests against the spec suites. The lesson that carries: build the test harness before the optimisations.

§2.5, §2.11 not done

No static evidence index, on purpose

  • Koka indexes a canonical vector at an offset known at compile time
  • That needs a closed row at the perform and a vector of exactly that shape
  • EYG rows inside let bound functions are open
  • Inference unifies rows, there are no open coercions to rebuild vectors at call boundaries
  • A non-scoped resumption can run under more handlers than its type names

An inline cached property access by label gets most of the way, without an elaboration pass.

Point at the insight: the static index is an artefact of subsumption being explicit in Koka's core. EYG's HM with rows does not produce those coercions.

§2.12.2 the subtle part

A resumed clause must find its evidence again

handle Ask((_, k) -> { k(1) }, (_) -> {
  handle Evil((_, k) -> { Suspended(k) }, (_) -> {
    handle Tl((_, resume) -> {
      let _ = perform Ask({})
      let _ = perform Evil({})     // escapes
      resume(perform Ask({}))
    }, (_) -> { Done(perform Tl({})) })
  })
})
// later: resume k under a reader that answers 2
  • The clause runs in place under under Tl
  • The resumption captures the under frame
  • Fixing the old vector is well typed and returns 1
  • underk looks up Tl in the vector current at resume and returns 2
  • Both examples from §2.12 are tests, for every configuration
This example does not type check in EYG, a handler returning its resumption needs a recursive type. The compiler falls back to checking every call and still gets 2. Mention that fallback is what makes untyped programs safe.

§2.10 selective translation

Checked per call, from the callee's row

  • Koka skips binds for total functions; EYG decides per call
  • The effect annotation on a call is the part that generalises, it can read empty through a parameter, so the callee type is used
  • Lambdas are annotated with a closed row, calls in their body can keep the open one
  • Variables carry opened types, pure let bound functions are still checked: next to fix

V8 is not JavaScriptCore

On V8, tail resumption decides whether it runs

  • A clause that resumes starts the rest of the loop inside itself
  • JavaScriptCore eliminates those tail calls in strict mode, V8 does not
  • Without tail resumption or evidence, 4 million performs overflow V8's stack
  • mstate resumes under a lambda: overflows V8 at 10 000 operations in every configuration

Part two

Generators

JavaScript already suspends functions. What does that buy?

The translation

A perform is a yield, a call is a yield*

(function* (acc) {
  const t = yield {l: "Ask", v: $unit};
  return $int_add(acc, t);
})

let r = f(x);
if ($isGen(r)) r = yield* r;
function* loop(label, h, gen, input) {
  while (true) {
    const step = gen.next(input);
    if (step.done) return step.value;
    if (step.value.l !== label) {
      input = yield step.value; continue;
    }
    const resume = (x) => loop(…, x);
    return yield* h(step.value.v)(resume);
  }
}
No join points, no frames, no flag: the compiler is a third of the size
Where a perform goes

Up every yield*, and back down

Ergonomics

What generators make easy, and what they make hard

Easy

  • Output reads like the source
  • Locals survive suspension, no join points
  • Async hosts: drive the outer generator, await between steps
  • Stack traces show the generator chain

Hard

  • Colour: rows generalise, so every call result needs isGen
  • One shot: a second resume replays from the start, sound only because EYG is pure
  • Nesting: each resume starts a loop inside a clause, 10 000 effects overflow
  • The fix for nesting is the paper's tail resumptive optimisation

Design constraints

Three rules of the language shape every API

serialisableA DOM node or peer can not be a value. Handles, selectors, or describe instead.
no recursionA tree has no type. Trees are flat lists with depth, like DecodeJSON tokens.
monomorphicAn effect has one lift and one lower type. A signal holds a string.

And one freedom: a function argument with an empty row is pure, so the host may call it.

Takeaways

What the language taught

  • Types carry the optimisation. Rows remove checks and let hosts call back in.
  • Tail calls are semantics. On V8, tail resumption is the difference between running and overflowing.
  • Serialisable values push APIs toward data. Snapshots and renders need no lifetimes; handles leak.
  • No recursive types means flat trees, and no efficient map written in EYG.
  • Purity pays twice. Sound selective translation, and replay as multi-shot for generators.
